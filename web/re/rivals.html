Marks: V = verified (two tools agree: Hopper + Ghidra, or code + bytes of the game files), I = inferred, U = open. Tools: G = Ghidra export census/ghidra/decomp_*.c, H = Hopper export census/hopper/decomp.c, C = capstone tools/recomp/asm.py dis, D = data read from game/ (tools/re/events.py, tools/re/chunks.py, scratch scripts). Names: census/names_rivals.tsv. Earlier notes (re_rivals_ai, re_rival_personality, re_rival_turnback, re_racer_cap*, re_ai_interact) were re-checked; section "Corrections" lists what was wrong. Answer

  • A career rival is a data row. EventDesc +0xd4 holds 3 rows of 0x1c bytes. A row has a name, a car preset hash,

an AI skill 0..9 per difficulty, an optional car rating and an "aggression" byte. 313 rivals, 67 names. V (D, G, C)

  • Spawn path. 0x4b5df0 (start career race) copies the event into race globals, builds the player entrant, then calls

0x4b4040(count, event). For each rival it builds the car from the preset (0x4b26f0), tunes its upgrade levels to a rating (0x57f700 / 0x57f970), wraps it in a DriverInfo (0x5809c0, id 100+k, kind 2, grid k+1, skill at entrant +0x735, aggression at +0x736) and adds it (0x4322a0). Then traffic (0x4b3ac0) and the grid swap (0x4b6300). V (G, H, C)

  • Quick race has no event. 0x4b4040(count, 0) picks 4 random names (0x4b3a20, 48 names), a random tuner car

(0x4b3c60, 20 cars, never the player's model more than once, stock rating <= player rating + window), skill from a cumulative table by difficulty (0x4b4590: easy 0..2, medium 3..5, hard 6..8), aggression 1, and matches each rival's rating to the player's best car (0x4b4380). V (G, H, C, D)

  • Rating: 303 of 313 rivals have rating -1 = "copy the player's upgrade levels and tune to the player's ride rating

(+-5, widening)". 10 rivals (URL ladder and boss races) have 7, 8 or 9 = fixed target 140 + 63.1 x value on the 140..771 rating scale. V (G, H, D)

  • The AI reads one 523-float table (chunk 0x34b00, copied to 0x779c78..0x77a4a0 by 0x462070). It holds 10

per-skill records (stride 0x54 at 0x779ff8), 8 distance curves, 2 position curves, 8 player-factor pairs, the Block table, the quick-race skill table and the rubber-band period (0.3 s). V (C, D, G)

  • Rubber band = 0x44bd10, once per racer per 0.3 s. Scale = 1 + curve(distance, skill) + S x gain(position, skill),

then x max((f-1) x v(skill, rank) + 1, floor(skill)); stored in veh+0x404 as max(scale, 1.0) and in ctx+0x4b8 raw. It is neutral for the first 3..19 s (by skill). S = EventDesc +0x12c (0.8..1.2). V formula, I directions

  • The AI reads time as 4000 ticks per second (0x6cca38 = 0.00025). Older notes used milliseconds. V (C, D). 0x6cca38 has 260 references across the whole binary: it is a global clock constant, not something of the AI (external audit 2026-10-29).
  • Skill at entrant +0x735 and aggression at +0x736 is I: the constructor only copies arg5/arg6; which is which follows the caller's values. The rubber band reads skill. To make it V, read what each field is used for.

3. Rubber band (0x44bd10) and catch-up

Called from 0x44c550 for each racer. It runs only if: AIVehicle [ctx+0x46c] != 0, vehicle +0x18 == 0, [0x78a344] == 0 (not drag), [0x7361a8] == 0, and at least 0.3 s passed since [ctx+0x420]. V (G, H, C)

  1. scale = 1.0 (0x6b77dc). ctx+0x470 = target = 0.
  2. If [0x7360ac] == 0, [[0x7361f0]] != 9, [0x78a320] > 0 and the racer's action flag ([[ctx+0x3f8]+0x1f2]) is set, and the race clock

is past the neutral window (record +0x4c): target = player object [0x7361bc] (one player; with two players the one chosen by race position against [0x78a324]/2). Then 0x44c010(rivalCar, targetCar, &out1, &out2) and scale = [0x78a404 + 4*target.slot] x out2 + 1.0 + out1. V

  1. 0x44c010 (needs [0x78a400] != 0): d = (rival.progress - target.progress) x route length (metres, + = rival ahead).

out1 = lerp_skill(curveA_k(d), curveB_k(d)) + clamp(((speedRival - speedTarget) x -0.005) / (0.01 x d^2 + 1), +-0.05); out2 = lerp_skill(A[i], B[i]) with i = (target.pos - rival.pos) + 7 (+8 if negative), curves 0x779f38 / 0x779f78; lerp_skill = value A + (B - A) x skill / 9. V (G, C) Sample (curve 0, skill 0): d=-900 -> +0.13, d=0 -> +0.004, d=+640 -> -0.5 (rival ahead is slowed). Skill 9 uses the second group: +0.18 / +0.044 / -0.3. V (D) Direction of out2 (negative when the rival is behind in rank) looks odd and is not tested (I).

  1. If action flag and target: scale x= max((f - 1) x v + 1, floor). f = [[target+0xa8]+0xc] (what it is: U), floor = record +0x18,

v = pair table value at skill (0x779fd0 + 8*rank if f < 1.0 else 0x779fb0 + 8*rank, interpolated by skill, rank = target car byte +0xa taken as 1-based: I). Table values rank 1..4: f >= 1: 0.75/0.97, 0.6/0.7, 0.4/0.5, 0.2/0.2; f < 1: 1.02/0.5, 1.07/0.74, 1.17/0.81, 1.27/1.0. V values, I indexing

  1. veh+0x404 = max(scale, 1.0) (a rival is never slowed below 1.0 by this field) and ctx+0x4b8 = scale (raw). V (C: 0x44bfe9, 0x44bffe)

Who turns it on or off: quick race [0x78a400] = race options byte +0x1f (0x4b4a56, 0x43b199); career sets 1 (0x4b5f47). [0x78a404] (S, player 1) defaults to 1.0: reset 0x431e37 (RaceStatus reset 0x431df0). Writers: 0x4b541c (1.0, mode 4), 0x4b5f53 (career, event +0x12c), 0x4b65f2 (1.0, SkipFE); reader 0x44bed9. No other store in the text, so quick-race circuits keep S = 1.0 (V). [0x78a400] (gate) is set by Reset (1), 0x4b4a56 circuit, 0x4b4caa, 0x4b4edc, 0x4b50f2 (free), 0x4b5365/0x4b5416 (mode 4), 0x4b5631, 0x4b5a2a, career 0x4b5f47 (1), LAN 0x43b199; quick race = options byte +0x1f. 4. Speed, skill and difficulty elsewhere

  • Desired speed (0x44c550, per frame): v = routeSpeedByte x record+0x14 x ctx+0x4b8, capped by the car's own limit (vtable [obj+0xff] slot +0x10). The byte is read

from route node idx, idx = current node + jitter, jitter in [-(b+1), b] re-rolled every 5.0 s (0x77a498) with b = record +0x50; speed byte = (byte << 16) x 1/65536 at node +0x6a (array start; node stride 0x88, route base +0x27c). If the byte is 0 the code uses 30.0 (0x6ccac0). V (G, H, C), unit I

  • Drag only ([0x78a344] or [0x7361a8]): 0x422410 (kind 3 = AI racer) sets [driver+0x1fc] = 0x6b7c20[[0x78a40c]] = 0.93 / 0.97 / 1.0

(events 4, 9, 11, 17 use 0.93; all others and quick race use 1.0). 0x476840 (0x476d97) adds 0x6b70e0[difficulty] = 3.0 / 1.5 / 1.0 for the human racer, and for AI racers 0x6b70ec[difficulty] = 0.4 / 0.8 / 1.0 plus the record +0x24..+0x30 values. V (G, C, D)

  • Difficulty [0x78a3fc]: quick race = options +0x14, career = [0x75f240]. It picks the skill column (+0x10/+0x12/+0x14), the quick-race skill row, the drag tables,

+0x13c[difficulty], cash and the target time. It does not change the AI code. V (C, G)

5. Tournament points of AI racers (0x43eb00)

The race-manager update adds to each AI racer record +0x10: 1.0 x pointsTable[rec+0xc] x lerp(record+0x44, record+0x48, rec+0x24) x [0x78a380] x [0x700a18] for racers with ids 100+k (k < 4 - humans). It is the standing of the AI in point-based events. V code (G, H, C), role I.

7. Placement on the grid

  1. Entrants get grid byte +3: player = [0x78a334] = 4 (0x4b5df0, 0x4b4a4c), rival k = k+1 (1..3). V (C, G)
  2. Career: 0x4b6300(eventGridSlot): finds the rival with id 100+k whose grid equals the slot and swaps its grid byte with the player's.

Slot 1 (115 events) puts the player on pole and the first rival at the back; slot 2 (event 0). V (G, C, D)

  1. Quick race: 0x4b4610: one human = swap entrant 0 with a random entrant (rand % (rivals+1), game RNG [0x6f227c]); two humans = pair shuffle. V (G, H)
  2. At race start 0x422a70: for slot s = 1..4 find the entrant with that grid byte, make it with 0x422410 (kind 1 human, 3 rival, 0 remote), position from

0x422580(4, buf). Only slots 1..4 exist. V (G, H, C)

  1. 0x422580 uses the track markers ForwardStartingPosition / BackwardStartingPosition (0x21-hash, direction [0x78a2fc]); marker +0xc = slot index (0-based). If there

are fewer than 4 markers it computes: row (i/2) x 17.0 + 100.0 m along the route, lateral +3.0 / -3.0 m alternately (0x6b7c2c, 0x6b7c34, 0x6b7c30). V (G, C, D)

8. Turn-back, direction and driving line

  • Direction of every racer = vtable slot +0x40 = 0x45d640 = mov eax, [0x78a2fc]. Nothing in the racer AI turns a racer around. V (C, H, G)
  • The racer's path object type is its direction; it is built once when the ctx is created (0x44cd30, earlier note: not re-read, I) and grown per frame by 0x458cc0.

The traffic decider 0x59c210 shows the game's own reversal (path retype + clearing 8 cache bits). host/free.c already uses this for Free Run (see re_rival_turnback). I

  • Driving line = the route object (node records of 0x88 bytes, speed byte per node, future-point pools: goal 26, action 27, FuturePoints 27, FuturePoint 640; overflow chunks make them soft caps).

Slot pools do not fail when full (re_racer_cap_probe, I). The racer sees every car (human, rival, traffic) through the neighbour list built by 0x57a910 (16 cars max). I (earlier notes)

  • AI random numbers: world RNG at [[0x7361f8]+0x2d0] (0x4216b0 int, 0x4216f0 float), same xorshift as the global [0x6f227c] used for names, cars, skills and grid: s ^= 0x1d872b41; t = (s >> 5) ^ s; s = (t << 27) ^ t ^ s. V (G, C)
