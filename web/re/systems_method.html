RE Methodology 10 verified Speed.exe addresses Speed.exe (2003, x86)
Updated 2026-11-25 View raw Markdown (.md) Source on GitHub

One row per function start of pc/Speed.exe (17,368: Hopper 14,333 + 3,035 lifter starts Hopper lacks); all 13,739 lifted functions have a row. Columns: addr, system, confidence, how, evidence.

Method (tools/census/systems.py; rules in tools/census/sys_rules.py)

  1. Seeds: strings (direct, tables, pool neighbours, decompile literals), imports (census/imports_sites.tsv), addresses

in docs and q_*.py (doc -> system map; mixed docs skip lines with >3 addresses), PATCH headers. Strings in an unwind funclet count for its owner. Static CRT band 0x672000-0x6830a0: string/import evidence is forced to runtime.

  1. Propagation, 8 rounds: callers 1/sqrt(n), callees 0.5, vtable peers 0.5, pieces of one function 1.5, unwind owner 2.0,

nearest seeds in link order; far edges weigh less. Called from >=3 systems = runtime (hub). Then shared globals, then neighbour sandwich. Leftovers: EH glue and padding = runtime/low; the rest unknown/low.

  1. Confidence is rule-based, not a probability: high = seed score >=3, share >=0.6; med = >=1.4, >=0.5 (graph: early,

strong, >8 instructions); low = the rest.

Manual check (I read the Hopper decompile of every sampled function)

--sample N --seed S prints tag, evidence and decompile. agree = content fits; plausible = fits region and neighbours; unverifiable = stub or thunk, tag only matches neighbours; wrong; unknown = tagged unknown.

  • Seed 31337, n=50, after one rule fix: agree 19, plausible 9, unverifiable 9, wrong 6, unknown 7. Strict 19/50,

agree+plausible 28/50, with unverifiable 37/50. Target 40/50 NOT met. The fix came from this sample (3 rows: camera mover ctor, Loaded*SlotPool = assets, CRT file I/O = runtime), so it is not held out.

  • Seed 4242, n=24, held out, same rules: agree 9, plausible 5, unverifiable 5, wrong 2, unknown 3 (19/24 lenient).
  • Wrong tags are about 8-12% in both; the gap is unverifiable tiny functions and 11% unknown.
  • External audit 2026-10-29: of the 886 named functions, 419 (47%) had a different system in systems.tsv than in names.tsv

(normalised sound->audio, tuning/garage->car, blur->render). The strict agreement of 19/50 (38%) is the better estimate of the graph's accuracy, not "8-12% wrong". Rule now: a name with a system (V or I) overrides the graph tag (tools/census/scoreboard.py); tagged counts only med/high confidence or named functions.

  • Tuning samples: seeds 7, 101, 202; earlier reads: 1029 (n=50), 2026 (n=30).

Rerun

.venv/bin/python tools/census/systems.py (10 s; needs capstone and pefile from .venv). Writes census/systems.tsv and prints the table. Hopper live, Ghidra live and REA are not used.

Known weak spots

  • 0x480000-0x4a0000 mixes camera, track, rivals; some camera movers stay track (0x48df00, 0x48c820).
  • FEng 2D UI (0x4f0000-0x520000): canon vs hud is ambiguous, mostly canon/low.
  • A doc naming an address in passing seeds a wrong system (0x566e60, a pool allocator, is rivals/high).
  • Tiny stubs and thunks follow neighbours only; 1,560 lifted functions have no evidence at all (unknown).
  • Tried and rejected: tag a constructor by strings near the vtable it stores (agreed 37% with string seeds).
  • 0x684000+ holds ~4,400 unwind funclets, thunks, misaligned lifter seeds, padding (1,725 rows); they take the owner's tag.
  • Not mined: ref/ PS2 and NFSU1 notes, runtime coverage (census/cov/union.json).
