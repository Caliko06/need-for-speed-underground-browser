Scope: (a) bec/lalo docs/re/ai_stuck.md float readers + patch, (b) bec/tomas docs/re/ai_traffic.md patch 1 at 0x4539db, (c) bec/memo docs/re/ai_corner.md one-sided jitter. Tools: capstone 5.0.7 (the repo venv has it), full-.text scan of pc/Speed.exe, census/hopper/decomp.c. Nothing run. V = read at the address. The old bytes quoted below are the image bytes, hex, read from the file.

(b) and (c) are mechanically sound. (a) counts right but its diagnosis is wrong: the patch cannot remove the entries it is aimed at.

(a) lalo · 0x6b7680 (timer 0.4 s) and 0x6b7684 (speed 5.0 m/s)

itemverdictevidence
0x6b7680 read only at 0x451c2e / 0x451eaf / 0x451ffbOK3 operand refs in all 2.7 MB of .text and 3 raw dword occurrences in the whole file. No pointer table to the float. V
0x6b7684 read only at 0x451c48 / 0x451c54 / 0x451ec5 / 0x45201b / 0x452027OK, 2 addresses off by one byte5 refs, same scan. But the 5th and 2nd are mov eax,[0x6b7684] whose opcode is at 0x451c55 and 0x452028; the doc cites the last byte of the preceding jnp. V
all 8 belong to "the three stuck finders"OK, naming imprecise0x451c2e/48/55 → sub_451b00 (action finder, returns 0x1f4 at 0x451c9b). 0x451eaf/ec5 → sub_451dc0. 0x451ffb/45201b/452028 → sub_451f10. The last two are boolean predicates (ret 4, return al 0/1) with no direct call anywhere; each address appears once in the file, as a dword in a function-pointer table in .rdata at 0x6c9188 / 0x6c918c, next to 0x451a70/0x452070. So the data patch also moves those two, which the doc does not mention. V
patch bytesOK0x6b7680 = cdcccc3e (0.4f) → 0000c03f (1.5f); 0x6b7684 = 0000a040 (5.0f) → 00004040 (3.0f). Both encode as intended. V
timer direction (1.5 is stricter, not looser)OK0x451c36 test ah,1; jne skip = fires only when age >= 0.4. V
0x424b50(speed,5.0,0.001) "can still veto, a rare escape roll"WRONG0x424b50 is fabs(a-b) <= eps: fsub; fabs; fcomp; jp; mov eax,1. It returns 1 only when speed is within 0.001 of 5.0, and the caller sets stuck on nonzero (0x451c6d je skip). No randomness, no veto. Net speed test: speed <= 5.0. V
"27-38 % of entries happen at >= 5 m/s, false positives of the 0.4 s trigger"WRONGThe contact branch can only set the flag with speed <= 5.0 (0x451c53 jnp + the equality band). An entry at 6-20 m/s came from the off-route branch (cross >= 20.0, 0x6b7690 = 20, jumps to 0x451bdb) or from modes 3/4 (0x6b7688 = 25, 0x6b768c = 20, 0x44e9c0(...)==1, also 0x451bdb). Neither reads the two floats, so changing them leaves those reversals untouched. V
"the car has been within 0.4 s of a contact"WRONG wordingIt is "at least 0.4 s since the contact entry" (age >= 0.4), the opposite of "within". V

Minor: 0x451dc0 tests the raw speed (no fabs), 0x451f10 uses fabs; a reversing car at -6 m/s satisfies speed < 5.0 and will keep flagging stuck. Only relevant if the -15/-6 m/s strength is ever touched (they said it is out of scope). V

semantic side effect not statedsee noteOld: exempt when flag […+0x90]+0x1c != 0 and my speed > 20 (0x6ccb4c), and the exemption returns -1 for the whole finder (0x453a07), i.e. no Avoid at all.
