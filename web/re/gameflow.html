Marks: V = a second tool agrees (H = Hopper export, G = Ghidra export, C = capstone over pc/Speed.exe), I = inferred or one tool, U = open. The binary outranks old notes. Names: census/names_gameflow.tsv (163 rows: 123 V / 40 I). Already done elsewhere and not repeated: EventDesc / save / languages (canon.md), garage screens (garage.md), HUD (hud_input.md), TRACKB streaming (track.md), the loaders and the ResourceFile layer (assets.md: 0x4482f0 CreateResourceFile, 0x448110 BeginLoading, 0x4483c0 ServiceResourceLoading ...).

Answer

  • The game flow is one global object at 0x77a904 holding "the next step". GameFlow::MainLoop 0x447600 runs that function pointer every frame

(clears it first, so a step must set the next one itself), and each step installs the next as a completion callback of an asynchronous file load. It is a continuation chain, not a switch. Eight state numbers (1..8) are written to [0x77a920] by the steps themselves (V H+C); the table also names a ninth, EXIT_DEMO_DISC, that nothing writes.

  • The cycle is: boot -> LoadingFrontEnd (1) -> InFrontEnd (3) -> UnloadingFrontEnd (2) -> LoadingTrackCommon (4) -> LoadingTrackSpecific (5)

-> Racing (6) -> UnloadingTrackSpecific (7) -> UnloadingTrackCommon (8) -> back to (1), or straight to (4) for a restart / next race. There is no separate "results" state: the results screens are FEng screens shown while the state is still Racing (I; see Open).

  • The front end is EA's FEng: FEManager (global [0x73578c]) owns a cFEng (+8) and a renderer (+0xc). Each .fng is a FEPackageData

record (list head 0x746104); activating one builds its screen object through the name -> factory registry at 0x6f94d8 (140 rows, stride 0x14). The 61 non-garage, non-online factories and their constructors are named from that table (V).

  • Only ~30% of the flow functions carried the right label in census/systems.tsv (audit below).

Triggers in detail (V unless marked):

  • Menu -> race: QuickRace::StartRaceByMode 0x4b5c00 switches on the mode [0x777cc8] (table 0x4b5d04: 0 circuit 0x4b49e0, 1 sprint 0x4b4c30,

2 knockout 0x4b4e60, 3 free run 0x4b5090, 4 0x4b52a0, 5 drag 0x4b55b0, 6 drift 0x4b59b0 (names of 4/5/6 from re_freerun_menu, I)), fills RaceStatus 0x78a2f0 and sets next = UnloadingFrontEnd. Career starts through Career::StartRaceFromEvent 0x4b5df0 (writer 0x4b62b3, same next).

  • SkipFE / direct start: 0x4b6390 copies the menu staging globals (0x734660.., 0x6f1d48..) into RaceStatus, creates the entrants with

0x5809c0(.., "SkipFE", ..) and spawns opponents; from state 3 it requests UnloadingFrontEnd, from any other state it jumps straight to LoadingTrackCommon.

  • Race end: Race::OnFlowMessage 0x422bb0 (vtable method; jump table 0x422c20, ids 1..10 -> cases 0,0,0,4,4,4,4,1,2,3) handles ids 9 and 10 by

setting next = 0x449a10 with name "BeginGameFlowUnloadingTrackSpecific" (id 10 first calls 0x495e90). Who sends 9/10 is U.

  • Restart: NOT 0x43ada0. Restart is race message 8 (see "Race coordinator states and object lifetime"); flow stays 6. Race::RequestStartOrRestart 0x43ada0

(only callers 0x546b41, 0x548721 = Net_HostStartRaceWhenAllReady 0x546980) is the online lobby start: SetNextUnloadingFrontEnd 0x448530 when IsInFrontEnd, else SetNextLoadingTrackCommon 0x448560. V (gap2)

3. How a step loads (the continuation pattern; V C/H)

file = CreateResourceFile(path, type, flags, ..) (0x4482f0), then BeginLoading(file, callback) (0x448110) with eax = callback; the step also writes [0x77a918]=1 and [0x77a91c]=<step name>. When the loader (0x4483c0, driven from the main loop and from 0x58a850) finishes the file, the callback runs and installs the next step. Steps that must not return before the data exists loop on 0x4483c0 themselves (INGAMEA.BUN in 0x449250; the waits in 0x448d10 / 0x4493a0 / 0x449a10 on a node's done flag). Two idioms to know when reading: (1) a callback pointer can be 0 (synchronous load); (2) after the load the step copies a path over the file node (FRONTEND\FRONTB.BUN over ...LZC, TRACKB%d.BUN, GLOBAL\INGAMEB.BUN) so the resource keeps its .BUN name (H+C loops at 0x448c17, 0x449811). Hopper and Ghidra miss the handlers that are reached only by pointer (0x448ac0, 0x449250, 0x449520, 0x449590, 0x449600, 0x449760): they appear as labels inside neighbouring functions, so the existing names 0x449765 and 0x44952b are mid-function addresses of 0x449760 and 0x449520.

4. FEng (front end engine; V unless marked)

Objects: FEManager [0x73578c] (ctor 0x4f5240, vtable 0x6c1b18; +8 cFEng 0x5254 B, +0xc FEngRenderer 0x3420 B), init 0x4f60e0 (also two screen pools [0x735dfc] 0x4c B and [0x735e18] 0x48 B used by PC_Loading and Chyron). cFEng keeps loaded packages in lists at +0xdc and +0xec; its back pointer to the manager is +0x10c.

  • FEPackageData record (list head 0x746104): +0x10 = chunk (id 0x30203 raw FNG, 0x30210 compressed "COMP"/"JDLZ"), +0x14 = screen object, +0x18 = package in cFEng,

+0x24 copied from the chunk. FNG header: magic 0xe76e4546, chunk "PkHd" 0x64486b50 at +8, version >= 0x20000 at +0x10, name hash at +0x28. Activate 0x4f3b60 creates the screen and prints "Activate %s\n"; Deactivate 0x4f3bd0 pops the package and deletes the screen; GetFngData 0x4f3c40 unpacks. FEPackageList::FindByName 0x4f3f90 (name in eax, list in the stack arg) is called from 300+ places: hash with FEng::HashName 0x4fd230, MRU move-to-front.

  • Registry 0x6f94d8: rows of 5 dwords (name, factory, flag, ?, hash). The flag is 1 for garage and list/browser screens (CreateScreen then also pushes MU_HorizontalBrowserBack.fng).

CreateScreen 0x4f37e0 takes the hash (h=-1; h=h33+toupper(c)), calls factory(&{name,arg,&row+0xc,row+0x10}); FindEntry 0x4f3940, SetFactory 0x4f39a0 (6 callers in 0x4dc600..0x4dcfd0) are the other users. Factory = operator new(size) (or a pool) + constructor; every constructor calls FEScreen::FEScreen 0x4f78e0 first (vtable 0x6c1874: slot 0 scalar deleting dtor 0x4f7b30, slots 1 and 5 the stub 0x4134b0) which itself calls FEScreenBase 0x4cd2a0 (stores the name hash at +8) and looks up shared objects by hash (0xaa68bfce, 0xaa68bfd4, 0xaa68bfc6 ..). Nine factories (twelve registry rows) build the base class directly: background, DiscError, MU_ScreenPos, LS_Demo_Legal, LS_THXMovie, LS_ESRB_PC, LS_Demo_Disclaimer, MU_UG_Explained and Chyron (4 rows, pool [0x735e18]). Nine more rows have factory 0 (GenericDialog, GenericOKDialog, MU_PauseConfirm, HELP_Generic ...: made by other code, U).

  • Messages are 32-bit hashes of names. Seen in handlers (garage.md + this pass): 0xc407210 accept, 0x911ab364 back, 0xb5971bf1 next item, 0x9120409e previous item,

0xc98356ba "screen shown again" (broadcast each frame by FEManager::Update 0x4f6170 through BroadcastMessage 0x4f3dc0), 0x35f8620b / 0x58c164c4 / 0x368a0075 / 0x541307a8 / 0x8816789f / 0x689e2e13 / 0x7f007e43 / 0xfd8a3b6d (option-menu moves, U), 0xabc08912 (U). Joystick events are the strings JOY_EVENT_FENG_* (0x6bb848..).

  • Package API wrappers: FEManager::ShowPackage 0x4f61f0 (name in eax: push if absent, then joy handlers 0x4f5ab0), cFEng::PushPackage 0x4eede0 (31 callers), cFEng::PopPackage 0x4eebf0.

0x4f6360 / 0x4f63a0 / 0x4f63e0 / 0x4f6430 are thin wrappers that find the active package with FindByName(…, 0x746104) and queue a command (0x4f0800 / 0x4eebf0 / 0x4f08f0 / 0x4f09b0): purpose per wrapper U.

5. Loading screens

  • PC_Loading.fng: factory 0x4dd230 (screen from pool [0x735dfc]), ctor 0x4dd290 (vtable 0x6c3778). GameFlow pushes it with FEManager::ShowPackage in LoadingFrontEnd 0x448b10 (@0x448b97, when no package is active), in

LoadingTrackCommon 0x449250 (@0x4492ca, only when [0x7183c8]==0) and in UnloadingTrackSpecific 0x449a10 (@0x449a7e). The screen has no per-step progress code read yet (U); the steps only publish [0x77a91c] and the timing floats. Chyron*.fng and LS_*.fng (Splash, EAlogo, PSAMovie, THXMovie, IntroFMV, LangSelect, Disclaimer, ESRB) are the boot screens (factories in the table below).

  • Boot order before the first menu: 0x401520 (named DiscCheck_ModalFrameLoop in names_render.tsv) shows DiscErrorPC.fng while 0x411ab0 fails; then the state chain starts.

Race coordinator states and object lifetime (2026-11-06)

V = code read, I = inferred, U = open. Sources: scratchpad gap2 and gap4 (REA, Ghidra, capstone).

What [0x7361f0] is. The RaceCoordinator, built by 0x421f00 ([0x7361f0] = this), message driven. [coord+0] = state. Only the pump 0x421b10 writes it: message 1 sets *coord = arg, message 2 (leave) writes 0 after the handler. Handler = table 0x700db8[state] (12 entries). The game loop 0x447600 queues message 3 (tick) every frame. 0x421ae0(N) = transition helper: queue 2 (leave), 1 (enter N), 3 (tick). Fields: +4 enter stamp, +0x14 "next mode" (4 / 2 / 9 / 10 at start, 8 = results), +0x18 initial stage, +0x20 state saved by pause, +0x24 paused byte. V

  • Test state == 8 || (state == 1 && [coord+0x14] == 8). Never use 7 (pause) or 5 / 6 (replay): they return to 4. A plain "state == 1" also fires on the grid. V
  • Racer finished flag: Race = [0x73619c], racers at Race+0x520 + 4*i, count [Race+0x24]; short racer+0x10 = finish reason, 0 = still racing. Rivals may finish before the player. V
  • A finished rival (car+0x24 == 3): FinishCar sets [ctrl+0x3f4] = 0x11 (0x43532c) -> AIActionEndOfRace ctor 0x453730 (priority 600), plan with zero speed: it brakes to a stop in place. V
  • Pause "quit to results" (state 7 arg 2) goes by msg 8 with no 0x423f20; whether racers get FinishCar there (0x495e20): U.

Restart and next race (V). Restart = race message 8 (posters 0x42395e, 0x4243e3, 0x4973b1 DoRestartRace). 0x422bb0 case 8 (0x422bd4): call 0x422130 (tear down) then call 0x421f00 (build again); flow stays 6; [0x7361f0] keeps its address. Msg 9 (DoRestartEvent 0x4973d0, DoNextRaceInEvent 0x497410, handler 0x423530 case 9) -> state 0 handler 0x422bed -> 0x449a10: flow 6 -> 7 -> 8 -> 4 (career retry, [0x778898] in {0,3}, gate in 0x4493a0) -> 5 -> 6. Msg 10 (quit): 7 -> 8 -> 1 -> 3. Build order in 0x421f00: PlaceAllRacers 0x422a70 (call at 0x421fc7) runs BEFORE the records 0x434590 (call at 0x422047). Car fields: car+0x14 = entrant, car+0x2c = driver. Free + build run inside one guest handler; during the 4/5/7/8 loading frames [0x7361f8] and [0x7361f0] are 0, so code gated on flow 6 never sees freed cars.

Race block reset (V, gap3). RaceStatus 0x78a2f0..0x78a427 (+ entrant pool 0x77c790) is reset by 0x431df0, not by track load. Callers: 0x448b3f (LoadingFrontEnd, flow 1), 0x4b5c15 (StartRaceByMode), 0x4b5d33 (LAN start), 0x4b5e18 (Career::StartRaceFromEvent). Flow 4 / 5 / 6 never store into it. Restart and 8 -> 4 keep it; 8 -> 4 re-copies only track, laps, direction ([0x78a2f0], [0x78a318], [0x78a31c], [0x78a2fc]) through 0x4abc20.
