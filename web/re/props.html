Props: smackable street objects (Speed.exe PC)

Tracks, Roads & Props 41 verified Speed.exe addresses Speed.exe (2003, x86)
Updated 2026-11-25 View raw Markdown (.md) Source on GitHub

Marks: V = verified (two tools agree, or code + file bytes), I = inferred, U = open. Tools: H = Hopper export, G = Ghidra export, C = capstone, F = game files (census/openworld_props.json, built from the TRACKB chunks). Prior notes in Spanish: re_props (this doc re-checks them and corrects two numbers).

Answer

  • A prop is smackable when a placed object of the base stream (0x34103 row in STREAML1RA.BUN) has an instance row

(0x34027, 0x70 bytes, TRACKB) whose class key exists in the class table (0x34026, 77 rows of 0x100). Everything else is static scenery (V F + H+G for the loader 0x5952a0).

  • 77 classes, identical in the 16 street tracks; 33 are placed, 44 unused. 4,580 instance rows, 1,122 unique

positions (V F). Class = name, rigid-body params (mass +0x20, inertia, centre of mass +0xb0), release limit +0xc4, durability +0xc8, life +0xc0, surface +0xd4 and smack type +0xdc (16 types: cones, signs, drums, fences...).

  • Life cycle: every instance starts as a cheap "Virgin" (0x5962e0, pool VirginSmokeableSlotPool); on contact

the broadphase turns it into a full "Smokeable" rigid body (0x596570, 32-slot pool); hit 0x597980 decides absorb or release. A settled smokeable becomes a Virgin again in its original place after 2.0 s (respawn), or is removed after its class life time if it has one (0x5977f0). V (H+G).

  • Reset: 0x595bf0 frees and rebuilds both pools at track load; 0x595d80 makes the Virgins; saved/restored per

slot by 0x595f70/0x596f50 (index 0xffff = none). V (H+G for 0x595bf0, 0x595f70, 0x596f50; G+C for 0x595d80).

Data (chunks in TRACKB<id>.lzc, loader index 29 of the table at 0x7007e0 = 0x5952a0 (an earlier draft said "loader 3", wrong; index 3 is 0x442040; external audit 2026-10-29) -> array 0x734470, count 0x734474)

Instance 0x34027 (0x70): +0 class key, +4 s16 section id, +6 s16 placement index in the section, +8 model hash, +0xc runtime Virgin pointer, +0x10/+0x20 AABB min/max, +0x30 4x4 world matrix, +0x60 translation (= placement position, error < 0.01 over 4,580). V F. Class 0x34026 (0x100): +0/+4 runtime links (list 0x737778), +8 name[24], +0x20 rigid-body block (mass -> body+0x144, 1/mass -> +0x148 in 0x584b10, V H+G), +0x80 key (first duplicate wins), +0x84/+0x88 emitter keys, +0x8c child count (0 in all PC data), +0xb0 centre of mass, +0xc0 life seconds, +0xc4 release limit (-> body+0x15c), +0xc8 durability (-> +0x160), +0xd4/+0xd0 surface hash/index (29-row table 0x6ef2d0), +0xdc/+0xd8 smack type hash/index (17 names at 0x6ef240). V F + G. Collision shapes: TRACKB 0x80034020 -> 0x39200/1/2 triples (88 shapes; all 77 classes have one, 11 extra are vehicles), found by key through 0x472c60; no shape -> default box +-1.5 (0x473cf0). V H+G (0x472c60).

Life cycle in detail

  1. 0x595bf0 (from 0x41f6e0): pools Virgin (max(count,1) x 0x68, 0x734464) and Smokeable (32 x 0x4d0,

0x734468); factory 0x73168c = 0x595230. V H+G (0x4d0 in both).

  1. 0x595d80: per instance, find the class by key; unless excluded by 0x595b70 (only event 0x4b1 with

XO_CONSTRUCSIGNA, V H+G), build a Virgin 0x5962e0: stores instance (+0x60) and class (+0x64), writes inst+0xc, clears bit 0x10 of the placement flags (= visible), registers the AABB (0x468680). Dtor 0x5964c0 sets it again.

  1. 0x445b00 (section loader 0x4457c0): placement bit 0x10 set when the instance has no Virgin, so a class-less

instance hides its placement (21 rows: XO_STOPSIGNA, XT_BUSHA). I (render mask not traced).

  1. Contact: 0x469580 (from 0x420380) -> 0x469670: car AABB vs object AABB, ignore matrix, slot-0x14 predicate

0x5927d0 (byte [this+0x1b]==0, C), object type 2 = Virgin -> 0x596570 builds the Smokeable if the active pool is not full (else no smack). V H+G for 0x469580, 0x596570.

  1. Hit 0x597980 (vtable slot 18): release limit 0 -> released at once (0x597c90, flag +0x4c2); else impulse below

the limit is absorbed. V H+G (0x4c2 in both). 8 of the 33 placed classes have a limit > 0: CS_STREETSIGN_B, ZCS_BridgeGateB, ZCS_BusSignPostA, ZCS_Chevrons, ZCS_GardenGate, ZCS_GateKnockA, ZCS_ParkgateA, ZCS_WaterBarrel (V F; the earlier note said only CS_STREETSIGN_B).

  1. Update 0x597420; respawn/expire 0x5977f0 (G read): if the instance link +0x170 is set, the body is at rest

(+0x168 = 0 or 0x7fffffff), byte +0x1a = 0 and more than 2.0 s (0x6ccc00) passed since +0x164 (clock 0x73ad34 x 0.00025 s), it rebuilds a Virgin from the instance and deletes itself; else if a timer +0x168 runs and class life +0xc0 != 0 and has passed, it kills the object (vtable +0x7c). V H+G (same callees, 0x7fffffff). Byte +0x1a meaning (on screen?) U.

  1. Pool cleanup 0x595670/0x595750: forced when fewer than 4 slots are free, else every 128 frames

(0x8000007f mask). V H+G.

Second-tool agreement (10 sampled names)

H and G show the same entry and callees, and share these constants: 0x5952a0 (0x34026, 0x34027), 0x595bf0 (0x4d0), 0x596570 (0xffff), 0x597980 (0x4c2), 0x597420 (13/14 callees), 0x5977f0 (0x7fffffff), 0x595670 (0x8000007f), 0x595b70 (0x4b1), 0x596f50 (0x164), 0x584b10 (0x144, 0x148). 10/10 agree. 0x595d80, 0x445b00, 0x469670 are not separate functions in the Hopper export (called only): G/C only.
