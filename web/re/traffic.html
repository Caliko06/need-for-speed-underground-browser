Marks: V = verified (two tools agree, or code plus file bytes), I = inferred, U = open. Tools: H = Hopper export census/hopper/decomp.c, G = Ghidra export census/ghidra/decomp_*.c, C = capstone (tools/recomp/asm.py), F = the game files read with tools/re/chunks.py and a small parser (the checks are quoted in the text). Earlier notes (re_traffic_teleport, re_citygraph, re_ai_interact, docs/traffic_placement.md, docs/openworld_e_re.md) were used as leads, not as proof; section "Prior notes" lists what changed. Names: census/names_traffic.tsv (120 rows; V 67, I 49, U 4).

Answer

  • There is no spawner and no despawner. The number of traffic cars is fixed when the race is built; the cars are

placed once at race start and afterwards only moved ("teleported") or parked. Nothing in the traffic code deletes a car. V (H+G: 0x4b3ac0 creates entrants, 0x422a70 places them, 0x598600 only calls the move 0x599830 or the park 0x5832a0).

  • How many: n = s8 TrackInfo row[0xc0 + 2*level + dir] (level 1..3, level 0 = none, dir = 0 forward / 1 reverse).

Of the 31 track rows, 25 have 12 for every level; the rest range 6..22 (table below). At most 30 entrants exist (4 players/racers + 26 traffic): 0x4322a0 stops at 0x1e. V (H+G+C+F)

  • Which cars: only the 15 CarTypeInfo records with usage 2 are candidates, and each has a weight per "district".

Every shipped track id is >= 1000, which always selects district column 0. In that column only six models have weight 1.0: 4DR_SEDAN02, TAXI02, PANELVAN, PARCELVAN, PICKUP, SUV (equal odds). TAXI, AMBULANCE, COUPE, FIRETRUCK, 4DR_SEDAN, BUS, MINIVAN, HATCHBACK and HATCHBACK02 have weight 0 there and never spawn. V (H+G+C+F: 0x57d000, GLOBALB.BUN)

  • Where they start: at race start 0x422a70 calls 0x598bf0 once per traffic entrant. It tries, in this order,

a node on the race route (0x5991a0, only when a route exists), a designer spawn record (0x598c80, chunk 0x34124), and for Free Run a random road node (0x598fb0), 100 tries each. V (H+G)

  • Density near the player comes from one gate, the spacing 0x59b3e0: 99999 m (nothing is placed) unless the player

stands in a TRAFFIC_DENSITY zone (type 4) and no slow car is within 250 m of route; then min + rand * (max - min) metres from the zone, per traffic level (35..190 m in the files). V (H+G+F)

  • Recycling: TrafficTeleporter::DoTimestep 0x598600 runs each frame, reloads a timer of 0.3 s (route) or

1.0 s (Free Run), then checks 22 cars (route) or 1 car per tick. A car that is parked, or has been passed and is hidden, is moved ahead of the player: designer spawn record first, else a walk along the road graph 250 m ahead (limit 500 m route distance). If no spot is found the car is parked (+0x4d1 = 1). V (H+G)

  • AI: traffic drivers are kind 3 (class with vtable 0x6b96b0, update 0x583350). Goal 4/5 selects, in order,

ObeyTrafficIntersections (priority 600), AvoidAvoidableAsTraffic (300), else a lane drive. Traffic does not react to being hit and honks at the player within 50 m. V (H+C for the goal cascade) I (the rest)

  • Collision with the player: no traffic-specific collision code was found in the traffic functions; traffic cars are

ordinary car bodies in the 30-body car pool. The only "hit" logic in the AI (IJustGotHit) is for racers. I, U for scoring.

Intersection (0x34123, 0x170 bytes)

Reached from a node by 0x44d570 (bits 20..24 of [node+0x84] x 0x170 + [0x736158], H+G). In the file: +0 u32 = 1 (all 49), +4 u8 section A, +5 u8 section B, +8 u16 node in A, +0xa u16 node in B, +0xc s32 = -1 (runtime current state), +0x10..+0x16f = 22 runtime items of 0x10 bytes (byte flag, s32 state 0..3, f32 time, f32), initialised to 0 / -1 / -1.0 / -1.0. V F: record k is referenced by exactly the two nodes (A, nodeA) and (B, nodeB) (49/49 in 14 files; example 1006 record 0 = section 102 node 13 and section 8 node 17). So an intersection is the crossing of two road sections. The runtime part is saved by TrafficIntersection (0x5aa9f0) and IncomingTrafficCar (0x5aaa90) (H+C: the strings are pushed there). I: 0x5aaf10 keeps +0xc only while an item for that state is live (time < 12.0 s); the stop/go choice is in 0x454490 via 0x5aaca0.

Level text (lang.py, English): TRAFFIC_NONE "None", TRAFFIC_LIGHT "Minimum", TRAFFIC_MEDIUM "Moderate", TRAFFIC_HEAVY "Maximum" (V F). That level 1/2/3 are these three is I. 1202 at level 3 asks 22, so 26 entrants fit under the cap of 30.

TRAFFIC_DENSITY zone (type 4 row of 0xb4 bytes in 0x3414a, inside container 0x80034147)

+0x7c holds 6 s32 = (min, max) spacing in metres for levels 1, 2, 3 (0x59b670 reads +0x7c + 4*(2L-2), 0x59b6a0 +0x7c + 4*(2L-1); C+G). V F: 31 files hold 0..6 such zones (45 in all); examples 1001 (80,95 / 50,65 / 35,45), 1202 (170,190 / 150,175 / 135,155). More traffic = smaller spacing.

Car records used by traffic (CarTypeInfo, 35 x 0xc90, [0x734588])

+0xc50 index, +0xc54 usage (0 tuner x20, 2 traffic x15), +0xc60 five f32 weights (districts 0..4), +0xd9 paint count, +0xc80 paint ids. Column 0 and paint counts: 4DR_SEDAN02 1.0 (8 paints), TAXI02 1.0 (1), PANELVAN 1.0 (6), PARCELVAN 1.0 (2), PICKUP 1.0 (8), SUV 1.0 (8); the other nine traffic types 0.0. District = 0 for ids >= 1000, else id/10 - 1 (60 -> 4); all 31 shipped ids are >= 1000 (V F), so columns 1..4 are unused. Traffic rides get no tuner skin slot (0x448f70 sets the entrant byte +0x17 to 0xff, I H).

How it runs

  1. Race build. Each mode setup (0x4b49e0 circuit, 0x4b5df0 event, others) sets [0x78a300] and calls

Race::SpawnTraffic 0x4b3ac0. For each of n cars: pick a type (0x57d000: weighted, retried up to 100 times to avoid a type already in the entrant list, then a repeat is accepted), pick a paint (rand mod [type+0xd9] -> [type+0xc80+i]), add an entrant of kind 3, id 0x32 + i (0x5809c0, 0x4322a0). No factor 1.5 appears here (the Free Run factor in docs/traffic_placement.md is U). V (H+G+C)

  1. Race start. 0x422a70 places players and racers, then each kind-3 entrant with 0x598bf0 (see Answer) and links the car into [0x7361f8].

0x5992f0 builds the car: driver mode (0x59b620 maps [0x78a3fc] 0/1/2 to 9/4/0), paint, goal 4 or 5, start speed. I (G)

  1. Each frame. 0x598600: updates intersections (0x59b6d0); if the level is nonzero, cars and players exist and the teleporter is enabled, the timer

runs down, 0x5988c0 asks "needs a move" (parked, or passed and not visible), 0x599830 moves it. V (H+G)

  1. Move 0x599830: pick a player (0x59b370). With probability 1.0 (0.35 if that player is below 20 m/s) try the spawn records

(0x599c80: needs records; side = rand < 0.5; window = the player's route position, +-60 m if a slow player is near, else a spot ahead; 0x599fc0 picks a record at random among those allowed; the car is put +0x70 + rand(+0x90 - +0x70) metres out at +0xb0 mph). Else route mode 0x5999c0 (a node 250 m ahead on the route) or Free Run 0x59a2c0 (walk the road graph 250 m from the player's node, doubling the step, give up past 500 m; side random below 24.5865 m/s, else the player's way). A spot needs a lane (0x5995e0), a drive flag (0x4420b0) and 0x59aa60: not inside the start clear zone, not within 250 m of a player's route (0x59ad90, race state 4), and not closer than the spacing to any other car (0x59b1e0). On failure 0x5832a0 parks the car. V (H+G)

  1. Despawn. None. Parked cars wait for the next move; the 500 m rule of re_traffic_teleport (free_recycle) is a host patch,

not in the game. I

  1. Driving. 0x583350: per tick one traffic car of N is updated (round robin on [0x6f08a4], I); a car with +0x410 set only brakes; a failed route update

parks it. Goal selectors 0x44e020 / 0x44e140: if the action type is not 0x12 and the ceiling is <= 600, finder 0x4543d0 (intersection, priority 600); if the type is not 3 and the ceiling is <= 300, finder 0x453920 (car ahead in my lane within 5 m, priority 300). 0x453c60 changes lane (5 lanes) or drops to 6 m/s at 15..30 m and 0 at <= 15 m. 0x44c2e0 honks at the player within 50 m. V (H+C) for the cascade, I for the rest (re_ai_interact section 3)

  1. Collisions. Traffic cars use the common car body (CarCollisionBodySlotPool, 30 bodies; re_racer_cap). Parking increments a counter at

[[veh+0x3c]+0x1b] (U what tests it). Racers avoid traffic through the shared neighbour list (re_ai_interact section 4, I).

Placement rules in detail (V asm, 2026-11-06; scratchpad gap1):

  • 0x59b1e0 (Spot_NearOtherCar) walks the WHOLE car list [0x7361f8] (players, racers, traffic, parked or not). Metric = route position, not Euclid:

d = 0x443d60(node+0x38, car+0x814), wrapped to +-L/2 on a loop. Skips self, any car with byte [car+0x8a8] != 0 (meaning U) and, when flag == 0 (teleporter), cars with [car+0x4d0] == 0. Traffic car (entrant kind 3): near if |d| < spacing (31 m). Racer or player: near only if 0 < d < spacing, i.e. the spot is 0..31 m AHEAD of it; a racer 20 m ahead does not block.

  • 0x59aa60 has NO camera, frustum or line-of-sight test. "Out of sight" = route distance >= 250 m ([0x6b5a38], rule b, state 4 only) from every player. It is a pure predicate

but rejects every spot within 250 m of the player route, so it is wrong for placing rivals. Straight-line variants 0x59acd0 / 0x59b130 are dead code.

  • 0x59a2c0 Free Run move is the only candidate walk: one chain from the player's node (0x4563d0, 250 m, then step doubles from max(spacing, node length): about 250, +s, +3s, +7s), give up past 500 m.

There is no stored candidate list and no reusable generator: every path tests spots inline and then moves a TRAFFIC car (driver mode, goal 4 / 5), so calling it on a racer would corrupt its AI.

  • Failure: 0x5832a0 parks the car; it is looked at again when the round-robin cursor returns (1 s in Free Run). The 49 intersections are not a placement input (no call to 0x44d570 / 0x442100 in 0x598600..0x59b700).

Open

  1. Who writes the traffic level: [ebx+0x59d4] is read at 0x4b5e61 and no writer was found by a scan of the whole .text; the options block +0x18 feeds 0x4b49e0.

EventDesc +0x134 holds 0..3 (38 / 36 / 32 / 10 events) but no link to [0x78a300] is proven. The front-end "Traffic:" option is not traced.

  1. [0x78a3fc] 0/1/2 -> driver mode 9/4/0 (0x59b620): meaning unknown; the strings "Traffic mode" (0x6c8ce8) and "Traffic in mellow mode" (0x6c8cd0) have no direct reference.
  2. Free Run count 12 -> 18 (x 1.5) in docs/traffic_placement.md: not found in 0x4b3ac0.
  3. Car state setter 0x426110 (states 0..4) and the counter at [[veh+0x3c]+0x1b]: what each state does to collision and drawing of a parked car.
  4. Player-vs-traffic contact: no traffic-specific code found; the HUD string STYLE_TRAFFIC_HIT exists but no code referencing its hash was found; scoring of traffic hits is not located.
  5. Intersections: the gate 0x5aaca0, the 22 items and the type field (all files hold 1; 0x454490 has cases 2 and 3) are not decoded.
  6. CCrossTrafficEmitter / CrossTrafficEmitters (drag races, strings at 0x6b7d03 / 0x6b7d18) have no direct reference; the drag cross traffic is not covered here.
  7. Entry fields +8, +0xc, +0xf and node bytes +0x68..+0x7f; spawn record tables at +0x30 / +0x50; track row byte +0x6a; the "usage 1" car branch in 0x4b3ac0 (no record has it).
  8. District columns 1..4 of the traffic weights are dead for the shipped tracks (ids < 1000 only); whether any mode feeds a smaller id is not shown (I from the 31 rows).
