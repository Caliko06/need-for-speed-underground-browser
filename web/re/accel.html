Acceleration chain and the knobs that scale it

Driving & Physics 14 verified Speed.exe addresses Speed.exe (2003, x86)
Updated 2026-11-25 View raw Markdown (.md) Source on GitHub

Question from the OWNER: "0-60 in ~2.7 s feels too fast". Sources read this session: docs/re/physics.md, the archived feel notes (not published) §5, re_accel, census/hopper/decomp.c (0x46cff0, 0x4774a0, 0x46aa40, 0x585410), direct float reads of pc/Speed.exe. Marks: F = read in code/data this or a prior RE session (cited), I = inference/model output, NV = not verified (no build, no run).

1. Formula chain, force to speed

Per frame, PhysicsMover 0x4774a0: inputs -> per-wheel scales -> substeps 0x46aa40 (semi-implicit Euler, dt/n) -> 0x4783c0 -> CarState refresh 0x4789d0 (F, physics.md "How the pieces fit").

  1. Base torque Engine::ComputeTorque 0x46cff0 (F, decomp 0x46cff0):

T = curve(rpm) * Engine+0xa0 then * 1.05 if Engine+0x1d != 0 (float 0x700024, one reader only). curve = 9 samples 850..9000 rpm at Engine+0x200..0x220 (ctor 0x46c7c0), turbo samples +0x224..0x244 already folded into the curve by 0x575bc0 (F, physics.md, re_accel §3).

  1. Nitrous is added after that product: + curve(rpm) * info+0x2ac (F, same function). So nitrous L3 (6 s, strength

0.5) does not scale with the 1.05 constant, and is not on during a 0-60 (F/I: not pressed in the logged run).

  1. Wheel force F = T * gear * fd / r (F for the fields, I for the port): gears/fd at DriveTrain+0x54 /

phys+0x1b0.., r = 0.3266, fd = split*[0x1bc] + (1-split)*[0x1b8] (physics.md; re_accel §3).

  1. Drag is a body force, not a wheel term: body+0x1e8 * body+0x1e4 in 0x585410 (F). Stock phys+0x290 = 0,

so the shipped car has no body drag; the ported table integration uses k = 0.00043 (I, re_accel §7).

  1. Acceleration a = (F - k v^2) / mass, mass in tonnes, torque kN.m, force kN (F for units, I for the port).
  2. Shift: the acceleration table 0x581b30 rescans the shift rpm in 50 rpm steps from (idle+redline)/2; R34 lands at

7900 (F, re_accel §3). Each gear change costs ~0.25-0.4 s of torque interruption in the model (I, fitted there and re-fitted here).

  1. Weight: 0x576250 sets mass = row[0] * stock_mass, rows at spec chunk 0x2b0; L1/L2/L3 = x0.932/0.866/0.800

for the R34 (F, re_accel §4).

  1. Turbo: level rows at 0x520 are 9 floats copied to info+0x224 and added into the curve (F, tuning.md §1);

R34 stock peak 0.3428, turbo L1 0.3496 kN.m (F, re_accel §4).

  1. Engine / ECU / transmission change the curve and the rpm limits; transmission L3 only touches top gear and

out+0x1cc, so 0-60 is unchanged (F, re_accel §4).

The only in-exe global that scales acceleration without touching data chunks, per-car torque curves or mass is 0x700024: a 4-byte float, read once, single consumer. Mass/transmission/grip constants are per-level rows or per-car fields; patching those means either data edits in GLOBALB.BUN or a cave.

3. The OWNER's levels (F, re_accel §2)

R34 SKYLINE, spec (weight 3, susp 1, engine 0, turbo 1, nitrous 3, ECU 0, trans 3, tires 3, brakes 2, spoiler 0, gf 0): mass 1.5 -> 1.2 t, peak torque 0.3496, gears 1-2 and fd unchanged, tires never traction-limited (mu ~2 vs ~1 g demand), nitrous not pressed. So the relevant chain is: mass x0.8, turbo L1, x1.05, ~0.4 s per shift.

4. Port of the chain, calibrated (I: model, not a measurement)

Model: 9-point curve interpolation, a = (T*gear*fd/r - k v^2)/m, shift at 7900 rpm, dt 0.5 ms, target 26.82 m/s. Reproduces re_accel within 0.02 s:

Reference for scale: a stock 1.5 t R34 runs 3.56 s in the same model. k = 0.90 puts the OWNER's upgraded car at about stock time (3.57 s); k = 0.85 puts it behind stock (3.76 s). That is the trade the table shows.

6. Limits and open points

  • The patch is global: it slows every car with Engine+0x74 != 0 (AI included) and leaves nitrous untouched. If the

OWNER wants "calmer acceleration" as a player-only feel, this is too blunt; a cave on 0x46cff0 keyed on the player ride would be the surgical version.

  • No run, no build, no Chrome, no ghosts: every 0-60 here is model output. The one precedent is the logged Original

run, which the model matches to ~0.2 s at 5 s.

  • Whether the shipped game with the same save does 3.1-3.3 s is still NV (needs the Wine reference run the earlier

report asked for).

  • Alternative knobs not written as candidates: mass rows (GLOBALB.BUN data), per-car Engine+0xa0, the accel table

0x581b30 shift rpm (DAT_00700030). All need either data edits or a cave; parked.
